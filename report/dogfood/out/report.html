Finding details

F-01. OS command injection through an MCP tool argument Critical

SeverityCritical 9.3, CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N
Why this scoreThe MCP endpoint needs no authentication. One tools/call request with a crafted hostname runs an arbitrary command as the server user, with full read, write and availability impact on the server.
WeaknessCWE-78 Improper Neutralization of Special Elements used in an OS Command
OWASPMCP Top 10 (2025, beta) MCP05, Command Injection
Top 10:2025 A05, Injection
ASVS 5.0.0V1.2.5 (L1, Injection Prevention)
SOC 2 criteriaCC7.1, CC8.1
StatusFixed and retested, fix in 30c386a (protocol-ctf/solutions/ai-1/fixed-server.mjs); retested 2026-11-26: fixed: exploit is blocked

Description

The netops lookup tool passes its hostname argument into exec() inside a shell command string. A character denylist is applied first, but it doesn't cover every shell metacharacter, so a crafted hostname runs extra commands.

Impact

Anyone who can reach the MCP endpoint, including an AI assistant fed hostile input, can run commands as the server process and read its environment, which holds the server's API token.

Evidence

  • protocol-ctf/challenges/ai-agents/ai-1/server.mjs:26, protocol-ctf-exploits ai-1: Exploited: exec() runs the tool argument through a shell; the denylist is bypassable
  • protocol-ctf/challenges/ai-agents/ai-1/server.mjs:26, eslint node-security/no-shell-injection: Shell command built via string concatenation or template literal. An attacker who controls any interpolated value can execute arbitrary OS commands.

Reproduction

  • exploit: protocol-ctf/solutions/ai-1/exploit.mjs
  • negative control: protocol-ctf/solutions/ai-1/control.mjs
  • retest: npm --prefix protocol-ctf run verify

Remediation

Call the lookup with execFile/spawn and an argument array, with no shell. Validate the hostname against an allowlist pattern instead of a denylist.

F-04. Backend trusts a client-settable identity header Critical

SeverityCritical 9.3, CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:N/SC:N/SI:N/SA:N
Why this scoreAny caller that can reach the gRPC port can set the metadata header with no credentials and act as any user, reading and changing their account.
WeaknessCWE-290 Authentication Bypass by Spoofing
OWASPAPI Security Top 10 (2023) API2, Broken Authentication
Top 10:2025 A07, Authentication Failures
ASVS 5.0.0V4.1.3 (L2, Generic Web Service Security)
SOC 2 criteriaCC6.1, CC7.1, CC8.1
StatusFixed and retested, fix in 30c386a (protocol-ctf/solutions/grpc-1/fixed-server.mjs); retested 2026-11-26: fixed: exploit is blocked

Description

callerOf() takes the user from the x-authenticated-user metadata header whenever it is present, on the assumption that only the gateway sets it. The backend listener accepts direct connections, so a client can set it too.

Impact

Full impersonation of any account in the bank service.

Evidence

  • protocol-ctf/challenges/grpc/grpc-1/server.mjs:20, protocol-ctf-exploits grpc-1: Exploited: identity is taken from the client-settable x-authenticated-user metadata

Reproduction

  • exploit: protocol-ctf/solutions/grpc-1/exploit.mjs
  • negative control: protocol-ctf/solutions/grpc-1/control.mjs
  • retest: npm --prefix protocol-ctf run verify

Remediation

Accept forwarded identity only from the gateway, authenticated with mTLS or a signed token, and strip the header from client requests. Otherwise require the bearer token on every call.

F-06. Order filter is compiled and run as code Critical

SeverityCritical 9.3, CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N
Why this scoreThe filter string reaches new Function() past a character allowlist that can be bypassed, so code runs in the server process with no authentication.
WeaknessCWE-95 Improper Neutralization of Directives in Dynamically Evaluated Code
OWASPTop 10:2025 A05, Injection
ASVS 5.0.0V1.3.2 (L1, Sanitization)
SOC 2 criteriaCC7.1, CC8.1
StatusFixed and retested, fix in 30c386a (protocol-ctf/solutions/grpc-3/fixed-server.mjs); retested 2026-11-26: fixed: exploit is blocked

Description

The order stream builds a predicate with new Function from the client's filter expression. A length limit and a character allowlist don't stop property access, which reaches the server-side signing key.

Impact

Code runs in the order service. The payments signing key and the order data are exposed.

Evidence

  • protocol-ctf/challenges/grpc/grpc-3/server.mjs:31, protocol-ctf-exploits grpc-3: Exploited: order filter is compiled with new Function; the character allowlist is bypassable
  • protocol-ctf/challenges/grpc/grpc-3/server.mjs:31, eslint node-security/detect-eval-with-expression: Use template literals instead of eval() for string interpolation

Reproduction

  • exploit: protocol-ctf/solutions/grpc-3/exploit.mjs
  • negative control: protocol-ctf/solutions/grpc-3/control.mjs
  • retest: npm --prefix protocol-ctf run verify

Remediation

Replace the expression with a structured filter: field, operator and value, checked against a fixed list of fields and operators. Never compile client input.

F-09. Prototype pollution through settings patches grants admin Critical

SeverityCritical 9.3, CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:N/SC:N/SI:N/SA:N
Why this scoreEvery connection gets a guest session. One patch containing __proto__ changes Object.prototype for the whole process, so every session's admin check passes.
WeaknessCWE-1321 Improperly Controlled Modification of Object Prototype Attributes
ASVS 5.0.0V15.3.6 (L2, Defensive Coding)
SOC 2 criteriaCC6.1, CC7.1, CC8.1
StatusFixed and retested, fix in 30c386a (protocol-ctf/solutions/ws-3/fixed-server.mjs); retested 2026-11-26: fixed: exploit is blocked

Description

merge() walks client-supplied patches recursively and copies every key, including __proto__, into the session settings. A patch with __proto__.isAdmin makes every object inherit isAdmin.

Impact

A guest reads admin secrets. The change persists for every user until the process restarts.

Evidence

  • protocol-ctf/challenges/websockets/ws-3/server.mjs:10, protocol-ctf-exploits ws-3: Exploited: recursive merge copies __proto__ keys from client patches
  • protocol-ctf/challenges/websockets/ws-3/server.mjs:14, eslint secure-coding/detect-object-injection: Every key of an untrusted object is copied onto this target, so the caller chooses which field is written — including one they should not control, such as isAdmin

Reproduction

  • exploit: protocol-ctf/solutions/ws-3/exploit.mjs
  • negative control: protocol-ctf/solutions/ws-3/control.mjs
  • retest: npm --prefix protocol-ctf run verify

Remediation

Skip __proto__, constructor and prototype keys, and copy only own enumerable data. Better still, validate patches against a schema of known settings, or keep settings in a Map.

F-08. WebSocket authenticates by Origin with an unanchored pattern High

SeverityHigh 8.7, CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:N/VA:N/SC:N/SI:N/SA:N
Why this scoreA non-browser client sets any Origin header, and the trusted-origin pattern has no end anchor, so a lookalike host also matches. No session is needed to dump the live config.
WeaknessCWE-1385 Missing Origin Validation in WebSockets
OWASPTop 10:2025 A07, Authentication Failures
ASVS 5.0.0V4.4.2 (L2, WebSocket)
SOC 2 criteriaCC6.1, CC7.1, CC8.1
StatusFixed and retested, fix in 30c386a (protocol-ctf/solutions/ws-2/fixed-server.mjs); retested 2026-11-26: fixed: exploit is blocked

Description

The upgrade handler treats a request whose Origin matches the console pattern as authenticated, as if it had a session. Origin is set by the client, and the pattern matches any host that starts with the console origin.

Impact

Anyone can open the ops socket and read the full config, including the vault token.

Evidence

  • protocol-ctf/challenges/websockets/ws-2/server.mjs:12, protocol-ctf-exploits ws-2: Exploited: Origin header is used as authentication, matched by a regex without an end anchor

Reproduction

  • exploit: protocol-ctf/solutions/ws-2/exploit.mjs
  • negative control: protocol-ctf/solutions/ws-2/control.mjs
  • retest: npm --prefix protocol-ctf run verify

Remediation

Require the session cookie for every socket. Compare Origin exactly against an allowlist only to stop cross-site hijacking, never as authentication.

Impact

Remediation

Give the digest agent only post_digest. Keep vault access out of any agent that reads untrusted content, and treat model output as untrusted before it reaches a tool.

F-10. Password checked with a non-constant-time comparison Low

SeverityLow 1.7, CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:L/VI:N/VA:N/SC:N/SI:N/SA:N/E:U
Why this scoreRecovering a password from response timing over a network needs many samples and low jitter (AC:H, AT:P). The leak is partial (VC:L). Not exploited in this engagement, and no public exploit is known (E:U).
WeaknessCWE-208 Observable Timing Discrepancy
OWASPTop 10:2025 A07, Authentication Failures
SOC 2 criteriaCC7.1
StatusOpen

Description

Login compares the submitted password to the stored one with !==, which returns as soon as a character differs. The passwords are also stored in plaintext. The reference fix for F-07 doesn't change this.

Impact

In theory, response timing reveals how much of a guess is right. In this lab the plaintext storage matters more.

Evidence

  • protocol-ctf/challenges/websockets/ws-1/server.mjs:31, eslint secure-coding/no-insecure-comparison: Secret comparison with !== can leak timing information

Remediation

Store a salted password hash (scrypt or argon2) and compare with crypto.timingSafeEqual.
